# User Schema Documentation

The **Authentication Service** manages this schema to track core account credentials, enforce unique access parameters, and handle secure password storage lifecycle rules.

## Schema Definitions

| Field | Type | Required | Unique | Details / Validation |
| :--- | :--- | :---: | :---: | :--- |
| `_id` | ObjectId | System | Yes | Primary Key automatically generated by MongoDB. |
| `username` | String | Yes | Yes | Lowercase, trimmed string. Constrained to length between `1` and `15` characters. |
| `password` | String | Yes | No | Secure string constrained to length between `8` and `60` characters. Automatically stored as a salt-hashed value. |
| `email` | String | Yes | Yes | Lowercase, trimmed email address string. |
| `createdAt` | Date | System | No | Timestamp when the user credential record was generated. |
| `updatedAt` | Date | System | No | Timestamp when the user credential record was last altered. |

## Lifecycle Hooks & Hooks Operations

### Pre-Save Middleware (`pre("save")`)
Before an account entry is permanently committed to the database layer, the schema intercepts the data stream to handle cryptographic isolation:
* Evaluates if the `password` field has been freshly modified or newly initialized.
* Automatically generates a cryptographic salt layer and hashes the plaintext password via `bcryptjs` using a workload factor (rounds) of `10`.

### Instance Methods

#### `comparePassword(password)`
Exposes an explicit verification helper on instantiated documents to validate credential match.
* **Parameters:** `password` (Plaintext String)
* **Returns:** `Promise<Boolean>` (Returns `true` if input matches database hash, `false` if incorrect)
